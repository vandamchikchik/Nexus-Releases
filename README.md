# Nexus

Агрессивная синхронизация файлов в реальном времени между машинами Linux и Windows.

- **Нода** (`nexus-node`) — фоновая служба на каждой машине: следит за папками проектов, передаёт изменения по QUIC (UDP), применяет входящие атомарно.
- **Оркестратор** (`nexus`) — графическое приложение: подключение нод, проекты, связи Dev → Operative, правила, мониторинг, обновления.

Подробные требования и устройство — `docs/SPEC.md`, `docs/ARCHITECTURE.md` в репозитории исходников.

## Загрузка

Релизы: <https://github.com/vandamchikchik/Nexus-Releases/releases>

| Что | Linux | Windows |
|---|---|---|
| Нода | `nexus-node_X.Y.Z_amd64.deb` или `nexus-node-X.Y.Z-linux-x86_64.tar.gz` | `nexus-node-X.Y.Z-windows-x86_64.zip` |
| Оркестратор | `nexus-orchestrator_X.Y.Z_amd64.deb` или `nexus-X.Y.Z-linux-x86_64.tar.gz` | `nexus-X.Y.Z-windows-x86_64.zip` |

Требования: Linux x86_64 с glibc ≥ 2.35 (Ubuntu 22.04+, Debian 12+, Fedora 36+), Windows 10/11 x64.

Каждый релиз подписан (Ed25519). `manifest.json` + `manifest.json.sig` содержат размеры и BLAKE3 всех файлов; ноды и оркестратор при самообновлении проверяют подпись встроенным публичным ключом ([`keys/release-signing.pub`](keys/release-signing.pub)).

## Установка ноды

### Linux (systemd)

```sh
sudo apt install ./nexus-node_X.Y.Z_amd64.deb     # ставит службу и печатает код сопряжения
# или из tar.gz:
tar xzf nexus-node-X.Y.Z-linux-x86_64.tar.gz && sudo ./nexus-node install
```

- Служба: `nexus-node.service` (`Restart=always`), данные: `/var/lib/nexus-node`, лог: `/var/lib/nexus-node/node.log`.
- Порт: **7470/UDP**. Если включён файрвол: `sudo ufw allow 7470/udp`.
- Лимиты inotify поднимаются автоматически (`/etc/sysctl.d/90-nexus-node.conf`).
- Код сопряжения ещё раз: `sudo nexus-node pair-code`. Состояние: `sudo nexus-node status`.
- Удаление: `sudo apt remove nexus-node` (данные остаются) или `sudo nexus-node uninstall --purge`.

### Windows

Распаковать zip, в **PowerShell от администратора**:

```powershell
.\nexus-node.exe install
```

- Копирует себя в `C:\Program Files\Nexus\Node`, регистрирует службу «Nexus Node» (автозапуск, перезапуск при сбое), открывает 7470/UDP в брандмауэре.
- Данные и лог: `C:\ProgramData\Nexus\node`.
- Код сопряжения: `nexus-node pair-code`; удаление: `nexus-node uninstall [--purge]`.

### Другой порт / ручной запуск

`nexus-node install --listen 0.0.0.0:7500` · `nexus-node run` (на переднем плане) · `nexus-node help`.

## Оркестратор

Linux: `sudo apt install ./nexus-orchestrator_X.Y.Z_amd64.deb` → `nexus` (или ярлык «Nexus»). Windows: распаковать zip, запустить `nexus.exe`.
Состояние сети хранится в `~/.config/nexus-orchestrator` (Windows: `%APPDATA%\nexus-orchestrator`) — это мастер-конфигурация, её стоит бэкапить.

### Первая настройка

1. **＋ Нода** → имя, адрес (`192.168.1.10` или `host:порт`; можно несколько через запятую), роль (Dev / Operative), код сопряжения из `nexus-node install`/`pair-code` → **Подключить**. Нода принимает только этот оркестратор.
2. **＋ Проект** → имя.
3. Выбрать проект → **Разместить на ноде…** → для каждой ноды папка проекта (кнопка **Обзор на ноде…** показывает файловую систему ноды).
4. **＋ Связь** → Dev-нода и Operative-нода проекта, пресет правил (или свои оверрайды).
5. Кликнуть по связи на графе / **Активировать**. У проекта активна максимум одна связь; активация другой деактивирует прежнюю.

Ноды сами находят друг друга по адресам из конфигурации и синхронизируются напрямую; оркестратор для работы не нужен, только для настройки и мониторинга.

### Правила

Одна строка — `шаблон  операции`, синтаксис как у `.gitignore`, **последнее совпадение выигрывает**. Операции: `write`, `delete`, `write,delete` (= `all`), `none`. Комментарии — `#`.

```
**            write, delete    # всё
target/       none             # кроме сборки
Builds/       write            # сборки только дописываются, не удаляются
```

Правила задаются отдельно для направлений Dev → Operative и Operative → Dev; пресеты переиспользуются между связями.

### Конфликты

- Побеждает более позднее изменение (LWW).
- Dev выигрывает у состояния Operative, существовавшего до активации связи; изменения Operative после активации синхронизируются обратно по правилам.
- Заблокированные файлы (открыты другой программой, нет прав) повторяются до 1 часа, затем попадают в «Проблемы» как сброшенные.

### Мониторинг

Вкладки внизу: **Передачи** (очередь, скорость, прогресс больших файлов), **События**, **Проблемы**, **Горячие файлы**, **Ноды** (версия, онлайн, ошибки).

## Обновления

- Оркестратор проверяет последний релиз и предлагает обновиться; после обновления он назначает нодам целевую версию — ноды обновляются сами (подписанный бинарь, перезапуск службы).
- Ноды также раз в 3 часа сами проверяют последний релиз и подтягивают версию при встрече с более новой нодой.
- Вручную: `nexus-node update` или `nexus-node update --to 0.2.0`.
- Ноды с разными версиями не синхронизируются друг с другом (строгое совпадение версии в рукопожатии) — обновляйте все.

## Безопасность

- Транспорт: QUIC/TLS 1.3, каждая нода и оркестратор идентифицируются ключом Ed25519; ключи закрепляются при сопряжении, посторонние соединения отклоняются.
- Ноды принимают конфигурацию только от сопряжённого оркестратора.

## Сборка из исходников

```sh
cargo build --release -p nexus-node -p nexus-orch   # target/release/{nexus-node,nexus}
cargo test --release
```

Релиз (сборка Linux + кросс-сборка Windows через llvm-mingw, .deb/.zip/.tar.gz, подпись, загрузка): `scripts/release.sh [--publish]`. Нужен приватный ключ подписи `~/.config/nexus/keys/release-signing.key` (никогда не коммитится).
