# Nexus

Агрессивная синхронизация файлов в реальном времени между машинами Linux и Windows. Вся связь идёт через один reverse-сервер (frp). Вся инфраструктура разворачивается из оркестратора кнопками.

- **Нода** (`nexus-node`): фоновая служба на каждой машине. Следит за папками проектов, передаёт изменения по QUIC, применяет входящие атомарно.
- **Оркестратор** (`nexus`): графическое приложение. Машины, установка, починка, проекты, связи Dev → Operative, правила, мониторинг, обновления.
- **Reverse proxy**: Linux-сервер с белым IP. На нём работает frps, через который идёт весь трафик.

Подробные требования и устройство описаны в `docs/SPEC.md` и `docs/ARCHITECTURE.md` в репозитории исходников.

## Как это устроено

```
 оркестратор ──frpc──┐                ┌──frpc── машина A (нода)
                     ├──► frps (reverse proxy) ◄──┤
 оркестратор 2 ─frpc─┘                └──frpc── машина B (нода)
```

- **IP машин не появляется нигде, кроме оркестратора.** Единственный внешний адрес на машине — адрес frps в конфиге её frpc.
- Нода слушает только `127.0.0.1`, а соседей видит как локальные порты frpc (секретные прокси `sudp`). Прямых соединений и запасных путей нет: без frps связи нет совсем.
- Прямое подключение во всей системе одно: первичная настройка reverse proxy по SSH. Остальное SSH идёт через frp:
  - установка, переустановка и удаление нод;
  - первый вход на новую машину: через reverse proxy как jump-host.
- SSH-доступы и IP хранятся только в состоянии оркестратора и на ноды не попадают.

## Загрузка

Релизы: <https://github.com/vandamchikchik/Nexus-Releases/releases>

| Что | Linux | Windows |
|---|---|---|
| Оркестратор | `nexus-orchestrator_X.Y.Z_amd64.deb` или `nexus-X.Y.Z-linux-x86_64.tar.gz` | `nexus-X.Y.Z-windows-x86_64.zip` |
| Нода (ставится оркестратором сама) | `nexus-node_X.Y.Z_amd64.deb`, `nexus-node-X.Y.Z-linux-x86_64.tar.gz` | `nexus-node-X.Y.Z-windows-x86_64.zip` |

Требования:
- Linux x86_64 с glibc ≥ 2.35 (Ubuntu 22.04+, Debian 12+, Fedora 36+) и systemd;
- Windows 10/11 x64.

Каждый релиз подписан (Ed25519). `manifest.json` + `manifest.json.sig` содержат размеры и BLAKE3 всех файлов. Перед установкой и при самообновлении подпись проверяется встроенным публичным ключом ([`keys/release-signing.pub`](keys/release-signing.pub)). frp ставится закреплённой версии (0.71.1) с проверкой контрольных сумм.

## Оркестратор

- Linux: `sudo apt install ./nexus-orchestrator_X.Y.Z_amd64.deb`, затем `nexus` (или ярлык «Nexus»).
- Windows: распаковать zip и запустить `nexus.exe`.

Состояние хранится в `~/.config/nexus-orchestrator` (Windows: `%APPDATA%\nexus-orchestrator`). Это мастер-конфигурация: машины, SSH-доступы, токен frps, сеть. Её стоит бэкапить и не показывать посторонним. Второй оркестратор — та же программа с копией этой папки; оба равноправны.

### Первая настройка (вкладка «Машины»)

1. **Reverse proxy.** Нажать «Настроить reverse proxy…» и указать адрес, пользователя и пароль или ключ SSH (root или пользователь с sudo).
   - Наружу должен быть открыт порт **7000/tcp**.
   - Nexus подключится напрямую один раз и поставит frps и frpc как службы.
   - Затем поднимет свой локальный frpc и дальше ходит только через него.
2. **Машины.** Нажать «＋ Машина» и указать имя, адрес (так, как его видит reverse proxy), SSH-доступ и роль (Dev / Operative), затем «Установить». Nexus сам:
   - зайдёт на машину через reverse proxy;
   - определит ОС;
   - поставит `nexus-node` и `frpc` службами;
   - заберёт код сопряжения и подключит ноду.

   Вводить коды вручную не нужно. Linux: нужен systemd. Windows: нужен включённый OpenSSH Server (один раз: «Параметры → Дополнительные компоненты → Сервер OpenSSH»), пользователь — администратор.
3. На вкладке **«Сеть»** нажать **«＋ Проект»**, затем «Разместить на ноде…» (папка проекта на каждой ноде, есть «Обзор на ноде…»), затем **«＋ Связь»** (Dev → Operative, пресет правил).
4. Кликнуть по связи на графе или нажать «Активировать». У проекта активна максимум одна связь.

Ноды синхронизируются между собой через frps. Оркестратор нужен только для настройки и мониторинга.

### Поддержка в одну кнопку

- **🛠 Починить всё** (верхняя панель):
  - проверяет reverse proxy и каждую машину;
  - переустанавливает всё, что не отвечает: frps, frpc, ноду;
  - сохраняет ключи и связи нод.
- В карточке машины: **Переустановить**, **Доступ…** (сменить логин, пароль или ключ), **→ граф**, **Удалить** (снимает службы и данные ноды, файлы проектов остаются).
- Индикаторы машины:
  - **SSH**: SSH машины через frps;
  - **frpc**: нода опубликована на reverse proxy;
  - **нода**: нода в сети.
- **Задачи**: пошаговый лог каждой установки или починки. Упавшую задачу можно запустить снова кнопкой «Повторить».

### Правила

Одна строка — `шаблон  операции`. Синтаксис как у `.gitignore`, **последнее совпадение выигрывает**.
- Операции: `write`, `delete`, `write,delete` (= `all`), `none`.
- Комментарии начинаются с `#`.

```
**            write, delete    # всё
target/       none             # кроме сборки
Builds/       write            # сборки только дописываются, не удаляются
```

Правила задаются отдельно для направлений Dev → Operative и Operative → Dev. Пресеты переиспользуются между связями.

### Конфликты

- Побеждает более позднее изменение (LWW).
- Dev выигрывает у состояния Operative, существовавшего до активации связи. Изменения Operative после активации синхронизируются обратно по правилам.
- Заблокированные файлы (открыты другой программой, нет прав) повторяются до 1 часа, затем попадают в «Проблемы» как сброшенные.

### Мониторинг

Вкладки внизу:
- **Передачи**: очередь, скорость, прогресс больших файлов;
- **События**;
- **Проблемы**;
- **Горячие файлы**;
- **Ноды**: версия, онлайн, ошибки.

## Нода на машине (для справки)

Обычно всё делает оркестратор. На машине:

- Linux:
  - службы `nexus-node.service` и `nexus-frpc.service`;
  - данные и лог: `/var/lib/nexus-node`;
  - конфиг frpc: `/etc/nexus/`.
- Windows:
  - службы «Nexus Node» и «Nexus frpc»;
  - программа: `C:\Program Files\Nexus\Node`;
  - данные: `C:\ProgramData\Nexus\node`.
- Команды:
  - `nexus-node status`: идентичность, конфиг, состояние служб;
  - `nexus-node pair-code`;
  - `nexus-node update [--to X.Y.Z]`;
  - `nexus-node uninstall [--purge]`.

## Обновления

- Оркестратор проверяет последний релиз и предлагает обновиться. После обновления он назначает нодам целевую версию, и ноды обновляются сами: скачивают подписанный бинарь и перезапускают службу.
- Ноды раз в 3 часа сами проверяют GitHub, даже без оркестратора.
- Ноды разных версий не синхронизируются друг с другом (в рукопожатии требуется точное совпадение версии), поэтому обновлять нужно все.

## Безопасность

- Транспорт: QUIC/TLS 1.3.
  - Каждая нода и оркестратор идентифицируются ключом Ed25519.
  - Ключи закрепляются при сопряжении, посторонние соединения отклоняются.
- Поверх этого frp:
  - вход на frps по токену;
  - у каждой ноды и каждого SSH-туннеля свой секрет (`sudp`/`stcp`), поэтому без секрета до них не достучаться.
- SSH: ключ хоста закрепляется при первом входе (TOFU). Смена ключа означает отказ, а не молчаливое продолжение.
- Ноды принимают конфигурацию только от сопряжённого оркестратора.

## Сборка из исходников

```sh
cargo build --release -p nexus-node -p nexus-orch   # target/release/{nexus-node,nexus}
cargo test --release
```

- Сквозной тест `relay_install_sync_repair_remove` поднимает три локальных sshd (reverse proxy + 2 машины) в песочнице `NEXUS_SANDBOX` и проходит полный цикл: установка → синхронизация → kill -9 → «Починить всё» → удаление. Ему нужны `/usr/sbin/sshd`, frp 0.71.1 (`NEXUS_FRP_DIR`) и собранный `target/debug/nexus-node`.
- Релиз: `scripts/release.sh [--publish]`. Скрипт собирает Linux-версию и кросс-собирает Windows через llvm-mingw, упаковывает .deb/.zip/.tar.gz, подписывает и загружает. Нужен приватный ключ подписи `~/.config/nexus/keys/release-signing.key` (никогда не коммитится).
